# 通用 PPT 制作 Skill

中文说明 | [English](README.en.md)

调用名：`enterprise-data-ppt`。适用于工作汇报、产品介绍、技术方案、培训教学、研究和故事分享。

## 工作流程

1. 确认总页数、封面与收尾配置。
2. 选择风格，确认内容图标和右上角标识。
3. 生成图片预览，由用户选定最终方案。
4. 获得正式制作授权后，制作可编辑 PPTX，并逐页渲染检查。

默认中文、16:9。支持八种起始风格，也可使用品牌模板和参考图。数据分析规则仅在内容需要时应用。

## 安装

把本仓库完整目录放入 Codex 的个人技能目录，目录名保留为 `enterprise-data-ppt`。主文件和 `agents/`、`references/` 必须一同保留。也可以使用支持 GitHub 仓库安装的 Skill 安装工具。

## 使用

在对话中调用 `$enterprise-data-ppt`，并说明主题、受众和用途。例如：

> 使用 $enterprise-data-ppt，制作一份12页的产品介绍。先确认配置，再展示风格预览，选定后制作可编辑PPT。

## 文件

- `SKILL.md`：完整工作流程与约束。
- `agents/openai.yaml`：Codex 界面名称和默认提示。
- `references/styles-and-previews.md`：风格菜单与图片预览规范。
- `references/analysis-and-delivery.md`：内容组织、数据使用和成品检查标准。

## 运行要求

这是指导助手工作的 Skill，不是独立 PPT 生成程序。图片预览需要图像生成工具；正式制作需要文稿工具及可用的渲染检查能力。实际能力以运行环境为准。

## 适用场景与设计原则

本 Skill 把主题、想法或现有资料转为叙事清楚、内容有依据、保留原生可编辑对象的演示文稿。兼容调用名保留 `enterprise-data-ppt`，适用范围不限于企业数据分析。

- 工作汇报：背景、目标、进展、问题与下一步。
- 产品介绍：用户场景、价值、功能、演示和使用引导。
- 技术方案：需求、原理、架构、流程、接口、实施和验证边界。
- 培训教学：目标、概念、示范、案例、练习和回顾。
- 学术研究：问题、方法、结果、讨论、局限和后续研究。
- 路演与故事分享：按照受众和表达目标组织叙事，不强塞 KPI 或趋势页。

正文、数字、表格、数据图表及要求可编辑的流程图和架构图使用原生对象；照片、产品截图和插画使用图片。预览图用于视觉选型，不能直接拼接成正式 PPT。

## 可选风格

| 编号 | 方向 | 示例用途 |
|---|---|---|
| A | 商务蓝 | 正式汇报、项目介绍与提案 |
| B | 科技青 | 技术方案、科普与数字产品 |
| C | 深色高级 | 发布会、路演与主题演讲 |
| D | 清新绿色 | 培训、自然健康与公益主题 |
| E | 极简黑白 | 学术、摄影、设计与人文分享 |
| F | 靛紫现代 | 产品、创意与创新主题 |
| G | 暖灰橙 | 故事、文化与案例教学 |
| H | 主题或品牌定制 | 品牌色、模板与参考图 |

默认比较组合为 A/B/C/D，只有用户授权后才生成。每种风格使用相同主题框架，便于比较。正文图标、右上角标识、封面背景与末页背景分别确认，不从一个选项推断其他设置。

## 安装后的使用方式

默认个人技能目录为 `~/.codex/skills/`；自定义 `CODEX_HOME` 时，放入对应目录下的 `skills/`。目录名使用 `enterprise-data-ppt`，保留 `SKILL.md`、`agents/` 和 `references/`。已有同名目录时先备份，再决定是否替换。

界面显示名称为“通用PPT制作”，显式调用名为 `$enterprise-data-ppt`。说明主题、受众、用途和资料即可开始；已经明确的信息不重复询问。

更多示例：

> 使用 $enterprise-data-ppt，制作8页摄影入门培训，面向零基础学员。需要真实案例和可编辑概念图，以练习和回顾收尾。

> 使用 $enterprise-data-ppt，把我提供的需求整理成16页技术方案，保留架构、流程、实施步骤和待确认项。

> 使用 $enterprise-data-ppt，只修改现有PPT第4页和第7页，保留页数、模板与配色，检查修改后的溢出和遮挡。

## 工作流程的边界

总页数包括实际使用的封面、结尾和附录。用户可以明确修改比例、语言、模板或授权跳过预览；“看看某种风格”只授权预览，不自动授权正式制作。

涉及具体人物、产品参数、研究结果或时效事实时，需要核实或标明待补。不编造数据、引用、部署成效和验收结果；生成插画不能冒充真实产品照片或现场证据。非数据主题不必提供 Excel，也不强制加入经营分析页面。

正式交付应实际渲染每页，检查遮挡、溢出、字体、图片裁切、对比度和来源。结构校验通过不等于生成了 PPT，也不等于已在所有文稿工具中完成兼容性验证。指定模型能否使用取决于宿主环境，不保证某个模型始终可用。
